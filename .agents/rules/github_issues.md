# GitHub Issue Style Guide

When asked to write or create a GitHub Issue for this repository, ALWAYS follow this formatting and structural style:

1. **## Context**: Start with a Context section (or Description) that clearly explains the problem or feature, including background information on why it's necessary.
2. **## Implementation Plan**: Provide a detailed breakdown of how the issue will be solved. Break this down logically, for example, by component, layers (e.g., Application Logic vs. User Interface), or steps.
3. **## Acceptance Criteria**: End with an Acceptance Criteria section containing a Markdown checkbox list (`- [ ]`) of clear, testable requirements that must be met for the issue to be considered complete.
4. **Blocked By**: If the issue is blocked by another issue, mention it explicitly using bold text (e.g., **Blocked By:** #123) near the end of the Context section.

Always use clear, professional language, and format references to code (files, variables, classes) using inline code blocks.
